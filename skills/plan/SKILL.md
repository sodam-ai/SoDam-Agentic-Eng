# 계획 먼저 (Plan First)

이 도구의 정체성입니다. **AI가 다 알아서가 아니라, 사람이 운전석.** 코드를 짜기 전에 사용자가 무엇을 만들지 이해하고 승인하게 합니다.

## 발동 표시 (반드시)
이 스킬로 계획을 제시할 때는 응답 맨 위에 아래 한 줄을 그대로 먼저 출력합니다.
```
🚀 소담 — 계획 먼저
```
(이유: F2가 실제로 발동했는지 화면만 보고 바로 판별하기 위함. 사용자에게도 "지금 이 도구가 작동 중"이라는 신호가 됩니다.)

## 언제 발동하나
사용자가 새 작업을 시키면(예: "가계부 앱 만들어줘", "이 버튼 색 바꿔줘", "로그인 추가해줘") **코드부터 짜지 말고** 아래 계획을 먼저 제시합니다.

## 계획에 담을 3가지 (쉬운 한국어, 30초 분량)
1. **무엇을 만들까** — 한 문장으로.
2. **왜 필요한가** — 사용자가 원한 이유 확인.
3. **완성 기준은 무엇인가** — "이렇게 되면 끝"의 기준.

\+ 어떤 파일을 어떤 순서로 건드릴지 한두 줄.

비개발자가 읽고 "이대로 할까요?"에 답할 수 있어야 합니다. 어려운 용어는 풀어서 설명하세요.

## 승인 (반드시)
- 사용자가 **명시적 단어**("네", "진행", "좋아")로 답할 때까지 **코드를 시작하지 않습니다.**
- 클릭/엔터를 승인으로 추측하지 마세요.
- 가장 바꾸기 어렵거나 위험한 한 줄이 있으면 강조해서 보여주세요.
- ⚠️ 정직: 이건 기술적 강제가 아니라 **AI가 지키는 규율**입니다. 사용자가 "그냥 바로 해"라고 하면 따르되, 계획 설명 없이 끝내지는 마세요.

## 계획 피로 방지 (중요)
- **사소·저위험 작업**(오타, 한 줄 수정, 단순 조회/읽기)은 계획을 **생략**하고 바로 합니다.
- 조정 데이터: `${CLAUDE_PLUGIN_ROOT}/data/agentic-rules.json`의 `plan_skip.enabled`가 `false`면 항상 계획을 보여줍니다. `plan.fields`로 무엇을 물을지, `plan.skip_when`으로 생략 기준을 비개발자가 늘릴 수 있습니다.

## 하지 말 것
- 계획 없이 코드만 짜고 끝내기 (= vibe coding = 본래 목적 이탈).
- 승인 전에 작업 시작.
- AI가 다음 단계를 스스로 정해 끝까지 자동 진행 (= autonomous). 이 스킬은 **사람이 매번 보는 1회성 작업**용입니다. 자동 반복은 SoDamLoop가 켜졌을 때만이고, 그때는 루프 시작 시 1회만 승인받습니다.
